# CCSwitcher 强制本地代理设计

## 目标

CCSwitcher 的所有应用内网络请求必须通过 `127.0.0.1:7890`。本地代理未监听、连接失败或卡死时，请求必须报错或超时，不得改用系统默认网络直连。

Claude Code 不改代码：它当前已通过 `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY` 显式绑定 `127.0.0.1:7890`，实施阶段只复核该状态，不修改 shell 配置。

## 范围

CCSwitcher 以下请求统一强制走本地代理：

- Anthropic 用量查询
- OAuth 授权码交换、Token 刷新和账号资料查询
- 自定义中转站连接测试
- GitHub 更新检查和安装包下载

OAuth 登录时由 CCSwitcher 打开的外部浏览器页面不属于 CCSwitcher 进程，浏览器路由不在本次范围内。

## 方案

新增一个唯一的网络会话提供者，例如 `PinnedProxySession`：

- 使用独立的 `URLSessionConfiguration`。
- 在 `connectionProxyDictionary` 中同时启用 HTTP 和 HTTPS 代理。
- 两类代理地址都固定为 `127.0.0.1`，端口固定为 `7890`。
- 生产代码只能取得该会话，不再直接使用 `URLSession.shared`。
- 不提供无代理会话，也不在请求失败后创建默认会话重试。

`ClaudeService` 和 `UpdateChecker` 接收或持有这一会话。现有 401 Token 刷新和 429 延迟重试可以保留，因为重试仍使用同一个强制代理会话；它们不能改变网络路由。

## 数据流

正常路径：

`CCSwitcher → 固定代理会话 → 127.0.0.1:7890 → XPro → 目标服务`

故障路径：

`CCSwitcher → 127.0.0.1:7890 不可用 → URLSession 错误/超时 → 现有错误状态或提示`

故障路径中不得出现“再用 `URLSession.shared` 请求一次”或“移除代理配置后重试”。

## 错误处理

- 代理拒绝连接、无法连接或超时，沿现有调用链返回失败，不触发直连。
- 用量刷新沿用缓存/过期状态展示，但日志应能识别这是网络失败。
- 更新检查和下载沿用现有失败提示。
- 不记录 Token、Authorization 请求头或其他凭据。

## 测试与验收

先写测试并确认失败，再实现网络会话：

1. 测试 HTTP 代理启用，主机为 `127.0.0.1`、端口为 `7890`。
2. 测试 HTTPS 代理启用，主机为 `127.0.0.1`、端口为 `7890`。
3. 测试服务默认使用强制代理会话，而不是 `URLSession.shared`。
4. 静态检查应用源码中不再存在 `URLSession.shared` 网络调用。
5. 运行全部单元测试并构建 macOS 应用。
6. 现场验证：7890 正常时请求成功；将代理地址临时指向确定未监听的本地端口时，请求失败，且没有目标域名的直连连接。测试不得停止或破坏用户正在使用的 XPro。

## 非目标

- 不修改 XPro 配置、系统代理或路由表。
- 不修改 `~/.zshrc`、Claude Code Token 或账号数据。
- 不新增自动切换代理端口、DIRECT 回退或远程代理配置界面。
- 不引入系统防火墙规则；如以后需要操作系统级双保险，单独设计。
